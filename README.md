## 📖 Введение

MCP Bridge — это мощное браузерное расширение, которое через локальный мостовой сервис предоставляет веб-версиям больших языковых моделей возможность вызова инструментов по протоколу **[MCP (Model Context Protocol)](https://modelcontextprotocol.io)**.

Без API-ключа, без платной подписки: достаточно установить расширение в браузере, и такие ИИ-платформы, как DeepSeek, Tongyi Qianwen, Tencent Yuanbao и другие, смогут напрямую вызывать ваши локальные инструменты!

### Поддерживаемые ИИ-платформы

✅ **DeepSeek** | ✅ **Tongyi Qianwen** | ✅ **Tencent Yuanbao** | ✅ **Doubao**  
⏳ **ChatGPT** (в процессе адаптации) | ⏳ **Grok** (в процессе адаптации)

## ✨ Возможности

### Основные возможности

- 🔄 **Бесшовная интеграция** — автоматическое распознавание и перехват чат-запросов основных ИИ-платформ
- 🛠️ **Вызов инструментов MCP** — поддержка вызова локальных инструментов через стандартный протокол MCP
- 🌐 **Мультиплатформенность** — нативная поддержка нескольких основных ИИ-платформ
- 📦 **Многоуровневое управление инструментами** — управление наборами инструментов через двухуровневую структуру Service и Tool
- 🎨 **Визуализация состояния** — отображение состояния и результатов вызова инструментов в реальном времени
- ⚙️ **Гибкая конфигурация** — настройка поддерживаемых платформ и инструментов через файлы конфигурации

### Четырёхуровневый механизм защиты

Гарантирует, что вызов инструментов никогда не завершится неудачей:

1. **Разбор API** — разбор из сетевых запросов в реальном времени (основной способ)
2. **Разбор UI DOM** — извлечение из содержимого страницы (автоматический резерв)
3. **Повторное обнаружение** — повторное обнаружение из последнего сообщения одним нажатием (возобновление с контрольной точки)
4. **Ручной ввод** — запуск копированием и вставкой пользователем (окончательный резерв)

### Дополнительные возможности

- 🎯 **Многопутевая инъекция** — поддержка одновременной инъекции System Prompt в несколько полей тела запроса
- 🔧 **Интеллектуальное объединение конфигураций** — поддержка 3 форматов JSON, автоматическое распознавание и добавочное объединение
- 🚀 **Динамическая настройка порта** — возможность задать порт мостового сервиса на странице настроек
- 🗑️ **Управление сервисами** — визуальное включение/отключение/удаление MCP-сервисов
- 📝 **Настройка сайтов** — независимая настройка стратегии автоматической инъекции для каждой ИИ-платформы

### Возможности оптимизации производительности

- 💾 **Интеллектуальное кэширование** — большие результаты автоматически кэшируются, ИИ может получать их по частям по мере необходимости
- 🔍 **Потоковый поиск** — быстрый поиск ключевых слов в больших файлах
- 📍 **Точное позиционирование** — после поиска можно сразу получить контекст целевой строки
- ⚡ **По чуть-чуть, но многократно** — ИИ направляется на получение данных по частям, что позволяет избежать проблем с производительностью

## 🚀 Быстрый старт

### Предварительные требования

- Браузер на движке Chromium, например Chrome/Edge
- Python 3.8+ (если запускать мостовой сервис из исходного кода)

### 1️⃣ Установка браузерного расширения

1. Откройте в браузере `chrome://extensions/`
2. Включите **"Режим разработчика"** (переключатель в правом верхнем углу)
3. Нажмите **"Загрузить распакованное расширение"**
4. Выберите каталог `mcp-bridge-ru` из этого проекта

### 2️⃣ Запуск мостового сервиса

#### Способ первый: использовать исполняемый файл (рекомендуется)

1. Скачайте `mcp-bridge-server.exe` из [Releases](https://github.com/WongJingGitt/mcp_bridge_server/releases)
2. Запустите двойным щелчком, сервис запустится на `http://localhost:3849`

#### Способ второй: запуск из исходного кода

```bash
cd mcp_bridge_server
pip install -r requirements.txt
python utils/mcp_bridge.py
```

### 3️⃣ Настройка сервисов инструментов MCP

#### Расположение файла конфигурации

- **Windows:** `%APPDATA%\mcp-bridge\config\mcp-config.json`
- **macOS:** `~/Library/Application Support/mcp-bridge/config/mcp-config.json`
- **Linux:** `~/.config/mcp-bridge/config/mcp-config.json`

#### Пример конфигурации

```json
{
  "mcpServers": {
    "filesystem": {
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\"],
      "description": "Инструмент доступа к файловой системе"
    },
    "git": {
      "enabled": true,
      "command": "uvx",
      "args": ["mcp-server-git", "--repository", "C:\\myrepo"],
      "description": "Инструмент управления Git-репозиторием"
    }
  }
}
```

#### Поддерживаемые форматы конфигурации

Расширение поддерживает **3 формата JSON**, что упрощает копирование конфигурации из других мест:

<details>
<summary><b>Формат 1: полная конфигурация</b></summary>

```json
{
  "mcpServers": {
    "service1": { "command": "...", "args": [...] },
    "service2": { "command": "...", "args": [...] }
  }
}
```
</details>

<details>
<summary><b>Формат 2: один сервис</b></summary>

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:\\"]
}
```
После вставки будет предложено ввести имя сервиса
</details>

<details>
<summary><b>Формат 3: несколько сервисов</b></summary>

```json
{
  "weather": { "command": "...", "args": [...] },
  "database": { "command": "...", "args": [...] }
}
```
Автоматически распознаётся как содержимое mcpServers
</details>

### 4️⃣ Начало использования

1. Откройте поддерживаемую ИИ-платформу (например, [DeepSeek Chat](https://chat.deepseek.com))
2. Начните диалог, расширение автоматически внедрит список инструментов
3. Попросите ИИ вызвать инструмент:
   ```
   Помоги мне вывести список всех инструментов сервиса filesystem
   ```
4. Посмотрите состояние выполнения инструментов во всплывающем окне в правом нижнем углу ✨

## 🏗️ Принцип работы

MCP Bridge использует **трёхуровневую архитектуру**:

```
┌─────────────────────────────────────────────────────────┐
│                Уровень браузерного расширения            │
│  • Перехват запросов к ИИ-платформам                    │
│  • Инъекция подсказок для вызова инструментов            │
│  • Разбор и выполнение команд вызова инструментов        │
│  • Отображение состояния вызова инструментов             │
└────────────────────┬────────────────────────────────────┘
                     │ HTTP/REST API
┌────────────────────▼────────────────────────────────────┐
│          Уровень локального мостового сервиса (Flask)    │
│  • Управление сервисами инструментов MCP                 │
│  • Предоставление RESTful API                            │
│  • Преобразование протоколов MCP ↔ HTTP                  │
└────────────────────┬────────────────────────────────────┘
                     │ MCP Protocol (stdio)
┌────────────────────▼────────────────────────────────────┐
│             Уровень сервисов инструментов MCP            │
│  • Операции с файлами, сетевые запросы, выполнение кода...│
│  • Следование стандарту протокола MCP                    │
│  • Независимо работающие исполняемые программы           │
└─────────────────────────────────────────────────────────┘
```

### Ключевые компоненты

| Компонент | Ответственность | Технологии |
|------|------|--------|
| **Браузерное расширение** | Пользовательский интерфейс, перехват запросов, вызов инструментов | JavaScript, Chrome Extension API |
| **Мостовой сервис** | Преобразование протоколов, управление сервисами, API-шлюз | Python, Flask, MCP SDK |
| **Инструменты MCP** | Фактическая реализация функций (файлы, Git, базы данных...) | Любой язык (с соблюдением протокола MCP) |

## 🎯 Руководство по использованию

### Базовое использование

1. **Откройте ИИ-платформу** — перейдите на любую поддерживаемую ИИ-платформу (например, [DeepSeek Chat](https://chat.deepseek.com))
2. **Начните диалог** — расширение автоматически внедрит список инструментов в System Prompt
3. **Вызовите инструмент** — попросите ИИ вызвать инструмент:
   ```
   Помоги мне вывести список всех инструментов сервиса filesystem
   ```
4. **Проверьте состояние** — всплывающее окно в правом нижнем углу показывает состояние выполнения инструментов в реальном времени

### Использование четырёхуровневого механизма защиты

#### 1️⃣ Разбор API (основной способ)
**Работает автоматически** — настройка не требуется, по умолчанию вызовы инструментов разбираются из сетевых запросов в реальном времени

#### 2️⃣ Разбор UI DOM (автоматический резерв)
Автоматически переключается при сбое разбора API; требуется настроить в `config/api_list.json`:

```json
{
  "uiParsing": {
    "enabled": true,
    "priority": "api",
    "messageContainer": ".chat-message",
    "messageIndex": -1
  }
}
```

#### 3️⃣ Повторное обнаружение (возобновление с контрольной точки)
**Сценарии применения:** обновление страницы, ответ ИИ завершён, но автоматическое обнаружение не сработало

**Шаги:**
1. Нажмите значок **⏰** в заголовке плавающего окна в правом нижнем углу
2. Система повторно извлекает вызов инструмента из последнего сообщения
3. После обнаружения он выполняется автоматически

#### 4️⃣ Ручной ввод (окончательный резерв)
**Сценарий применения:** когда все автоматические способы обнаружения не сработали

**Шаги:**
1. Скопируйте ответ ИИ, содержащий `<tool_code>`
2. Нажмите на плавающее окно, чтобы развернуть его, и вставьте текст в поле ввода
3. Нажмите кнопку **"Отправить в MCP"**

### Функции страницы настроек

Откройте страницу управления расширениями браузера → нажмите «Подробнее» у MCP Bridge → нажмите «Параметры расширения»

#### Управление сайтами
- **Описание функции** — узнайте, как работает «автоматическая инъекция System Prompt»
- **Настройка сайтов** — независимая настройка стратегии автоматической инъекции для каждой ИИ-платформы
- **Настройка порта** — настройте порт мостового сервиса (по умолчанию 3849)

#### Управление сервисами
- **Включение/отключение сервиса** — управление состоянием сервиса переключателем
- **Просмотр состояния сервиса** — отображение состояния работы сервиса в реальном времени
- **Удаление сервиса** — удаление ненужного сервиса одним нажатием

#### Конфигурация сервисов (для продвинутых)
- **Поддержка 3 форматов** — полная конфигурация, один сервис, несколько сервисов
- **Интеллектуальное объединение** — автоматическое распознавание формата и добавочное объединение с текущей конфигурацией
- **Обработка конфликтов** — можно выбрать «автоматически заменять существующие сервисы» или пропускать

## 🔌 API-интерфейсы

Мостовой сервис предоставляет следующие RESTful API:

| Конечная точка | Метод | Описание |
|------|------|------|
| `/health` | GET | Проверка работоспособности |
| `/tools` | GET | Получить список всех сервисов (только имена и описания, без инструментов.) |
| `/tools?serverName=:name` | GET | Получить список инструментов указанного сервиса |
| `/execute` | POST | Выполнить инструмент |
| `/config` | GET | Получить текущую конфигурацию |
| `/config` | POST | Обновить конфигурацию и перезагрузить |
| `/reload` | POST | Перезагрузить конфигурацию |
| `/restart-server` | POST | Перезапустить указанный сервис |
| `/shutdown-server` | POST | Остановить указанный сервис |
| `/reset-history` | POST | Сбросить историю вызовов инструментов |

## 📁 Структура проекта

```
mcp_bridge/                    # Браузерное расширение
├── manifest.json              # Файл манифеста расширения
├── config/
│   └── api_list.json          # Конфигурация поддерживаемых ИИ-платформ
├── modules/
│   ├── api_client.js          # Клиент связи с мостовым сервисом
│   ├── prompt_builder.js      # Построитель подсказок для вызова инструментов
│   ├── input_injector.js      # Инъектор в поле ввода
│   └── compareVersion.js      # Утилита сравнения версий
├── scripts/
│   ├── background.js          # Фоновый скрипт (основная логика)
│   ├── content_script.js      # Контентный скрипт (взаимодействие со страницей)
│   └── page_world/
│       ├── injector.js        # Инъектор скриптов страницы
│       ├── fetchhook.js       # Перехватчик Fetch API
│       └── ajaxhook.min.js    # Перехватчик XMLHttpRequest
├── ui/
│   ├── status_panel.js        # Компонент панели состояния
│   └── status_panel.css       # Стили панели состояния
├── options/
│   ├── options.html           # Структура страницы настроек
│   ├── options.js             # Логика страницы настроек
│   └── options.css            # Стили страницы настроек
└── popup/
    ├── popup.html             # Структура всплывающего окна
    ├── popup.js               # Логика всплывающего окна
    └── popup.css              # Стили всплывающего окна

mcp_bridge_server/             # Мостовой сервис
├── utils/
│   └── mcp_bridge.py          # Основная программа Flask-сервиса
├── requirements.txt           # Зависимости Python
├── build.bat / build.sh       # Скрипты сборки
└── mcp_bridge.spec            # Конфигурация PyInstaller
```

4. **Тестирование функции**: проверьте, что вызов инструментов работает корректно

### Пример основной конфигурации

```json
{
  "name": "platform_id",
  "hostname": "platform.example.com",
  "label": "Название платформы",
  "api": ["/api/chat"],
  "promptPath": "prompt",
  "response": {
    "type": "sse",
    "contentPaths": ["content"]
  },
  "input": {
    "selector": "textarea",
    "submitKey": "Enter"
  }
}
```

Полное описание полей см. в [Полном руководстве по конфигурации API](docs/API_CONFIG_GUIDE_RU.md)

## ❓ Частые вопросы

<details>
<summary><b>В: Почему вызов инструмента не сработал?</b></summary>

**О:** Проверьте следующее:
1. Работает ли мостовой сервис (откройте http://localhost:3849/health)
2. Включена ли на странице настроек «автоматическая инъекция System Prompt»
3. Проверьте консоль браузера на наличие ошибок
4. Попробуйте функцию «повторное обнаружение» или резервный «ручной ввод»
</details>

<details>
<summary><b>В: Как изменить порт мостового сервиса?</b></summary>

**О:** 
1. Откройте страницу настроек расширения
2. Измените номер порта в разделе «Конфигурация мостового сервиса»
3. Нажмите кнопку «Сохранить»
4. Перезапустите мостовой сервис и используйте новый порт
</details>

<details>
<summary><b>В: Где находится файл конфигурации?</b></summary>

**О:** 
- **Windows:** `%APPDATA%\mcp-bridge\config\mcp-config.json`
- **macOS:** `~/Library/Application Support/mcp-bridge/config/mcp-config.json`
- **Linux:** `~/.config/mcp-bridge/config/mcp-config.json`
</details>

<details>
<summary><b>В: Какие инструменты MCP поддерживаются?</b></summary>

**О:** Поддерживаются все инструменты, следующие [протоколу MCP](https://modelcontextprotocol.io), включая:
- Официальные инструменты: filesystem, git, postgres, sqlite и др.
- Инструменты сообщества: любые программы, реализующие протокол MCP
- Пользовательские инструменты: ваши собственные MCP-сервисы
</details>

<details>
<summary><b>В: Как добавить поддержку новой платформы ИИ?</b></summary>

**О:** См. раздел [Руководство по разработке](#-руководство-по-разработке), отредактируйте `config/api_list.json`, чтобы добавить конфигурацию платформы. Подробности см. в [Полном руководстве по конфигурации API](docs/API_CONFIG_GUIDE_RU.md).
</details>

<details>
<summary><b>В: Почему некоторые сервисы отображаются как «остановлены»?</b></summary>

**О:** 
1. Проверьте правильность конфигурации сервиса (command и args)
2. Просмотрите логи консоли мостового сервиса
3. Попробуйте нажать «Перезапустить сервис» на странице настроек
4. Убедитесь, что необходимые зависимости сервиса установлены
</details>
