# Кэширование и функция поиска (v1.1+)

## Обзор

В MCP Bridge v1.1 добавлены интеллектуальное кэширование и потоковый поиск для эффективной обработки сценариев с возвратом больших результатов.

## Новые API-интерфейсы

| Конечная точка | Метод | Описание |
|------|------|------|
| `/result/{cache_id}` | GET | Получить содержимое кэша (с поддержкой сегментов) |
| `/search-cache` | POST | Искать ключевые слова в кэше |
| `/get-cache-context` | POST | Получить контекст указанной строки |

## Рабочий процесс

### 1. Автоматическое кэширование

Когда результат, возвращаемый инструментом, превышает порог (по умолчанию 1000 байт), сервер автоматически кэширует его:

```json
{
  "success": true,
  "result_type": "cached_reference",
  "cache_id": "uuid-string",
  "cache_type": "memory",  // или "file"
  "total_size": 30520,
  "message": "Результат слишком большой, закэширован"
}
```

### 2. Вызов инструментов ИИ

ИИ может использовать следующие три инструмента для работы с кэшем:

#### Поиск по содержимому кэша

```xml
<tool_code>
{
  "tool_name": "search_cached_result",
  "arguments": {
    "cache_id": "uuid-from-previous-result",
    "keyword": "error",
    "case_sensitive": false
  }
}
</tool_code>
```

#### Получение контекста указанной строки

```xml
<tool_code>
{
  "tool_name": "get_cache_context",
  "arguments": {
    "cache_id": "uuid-from-previous-result",
    "line_num": 23,
    "context_lines": 5
  }
}
</tool_code>
```

#### Сегментное получение содержимого

```xml
<tool_code>
{
  "tool_name": "get_cached_result",
  "arguments": {
    "cache_id": "uuid-from-previous-result",
    "start": 0,
    "end": 8000
  }
}
</tool_code>
```

## Характеристики производительности

- **Потоковый поиск**: постоянное потребление памяти (~10 МБ), поддержка файлов любого размера
- **Быстрый отклик**: поиск по файлу 10 МБ < 100 мс
- **Интеллектуальное кэширование**: 
  - Кэш в памяти: результат ≤ 10 КБ
  - Файловый кэш: результат > 10 КБ
  - Автоматическое устаревание: TTL = 5 минут

## Сценарии использования

1. **Чтение больших файлов** — чтение файлов размером несколько МБ: сначала поиск для определения местоположения, затем точное получение
2. **Анализ логов** — поиск информации об ошибках в большом объёме логов
3. **Запросы данных** — постраничный вывод при возврате большого объёма данных

## Параметры конфигурации

В конфигурации сервиса можно настроить поведение кэширования:

```json
{
  "mcpServers": {
    "your_service": {
      "max_output_bytes": 1000,        // Порог срабатывания кэширования
      "cache_large_results": true,      // Включить кэширование
      "result_cache_ttl": 300,          // Время жизни кэша (секунды)
      "max_memory_cache_size": 10240    // Порог кэша в памяти (байты)
    }
  }
}
```
