## Обзор

MCP Bridge использует **трёхуровневую архитектуру**, разделяя браузерное расширение, мостовой сервис и сервисы инструментов MCP, что обеспечивает гибкую и расширяемую систему вызова инструментов.

### Цели дизайна

1. **Разделение**: каждый уровень работает независимо, не мешая другим
2. **Расширяемость**: лёгкое добавление новых платформ и инструментов
3. **Отказоустойчивость**: многоуровневая защита обеспечивает стабильность сервиса
4. **Прозрачность**: незаметный для пользователя процесс вызова инструментов

### Первый уровень: Браузерное расширение

**Обязанности**
- Перехват сетевых запросов к ИИ-платформам
- Инъекция подсказок для вызова инструментов
- Разбор команд вызова инструментов в ответах ИИ
- Отображение состояния и результатов выполнения инструментов

**Технологии**
- JavaScript (ES6+)
- Chrome Extension API (Manifest V3)
- Перехват Fetch/XHR
- Работа с DOM

### Второй уровень: Мостовой сервис

**Обязанности**
- Предоставление RESTful API
- Управление жизненным циклом сервисов инструментов MCP
- Преобразование протоколов MCP ↔ HTTP
- Чтение/запись и горячая перезагрузка конфигурационных файлов

**Технологии**
- Python 3.8+
- Flask (веб-фреймворк)
- MCP Python SDK
- Управление процессами

### Третий уровень: Сервисы инструментов MCP

**Обязанности**
- Реализация конкретных функций (работа с файлами, сетевые запросы и т.д.)
- Соблюдение спецификации протокола MCP
- Независимая работа, возможность запуска и остановки в любое время

**Технологии**
- Любой язык (Python, Node.js, Rust и т.д.)
- Следование стандарту протокола MCP

## Подробное описание основных компонентов

### 1. Компоненты браузерного расширения

#### 1.1 Скрипт страницы (Page World)

Работает в основном контексте JavaScript веб-страницы, отвечает за перехват сетевых запросов.

**Основные файлы**
- `scripts/page_world/injector.js` — инъектор скриптов
- `scripts/page_world/fetchhook.js` — перехватчик Fetch API
- `scripts/page_world/ajaxhook.min.js` — перехватчик XMLHttpRequest

**Принцип работы**
```javascript
// Перехват Fetch API
window.fetch = new Proxy(originalFetch, {
  apply: async (target, thisArg, args) => {
    // 1. Проверить, попадает ли запрос в API ИИ-платформы
    // 2. Извлечь тело запроса
    // 3. Отправить в контент-скрипт для обработки
    // 4. Дождаться изменённого тела запроса
    // 5. Продолжить исходный запрос
  }
});
```

**Поток сообщений**
```
Page World → Content Script → Background → Page World
```

#### 1.2 Контент-скрипт (Content Script)

Работает в изолированном контексте JavaScript, служит мостом между скриптом страницы и фоновым скриптом.

**Основные файлы**
- `scripts/content_script.js`

**Обязанности**
1. Приём сообщений от скрипта страницы и пересылка в фоновый скрипт
2. Приём команд обновления UI от фонового скрипта
3. Управление жизненным циклом панели состояния
4. Выполнение умной инъекции ввода

**Ключевые функции**
```javascript
// Пересылка сообщений
window.addEventListener('message', (event) => {
  if (event.data.source === 'mcp-bridge-injector') {
    chrome.runtime.sendMessage(event.data, (response) => {
      window.postMessage({
        source: 'mcp-bridge-content-script',
        requestId: event.data.requestId,
        payload: response.payload
      }, '*');
    });
  }
});
```

#### 1.3 Фоновый скрипт (Background)

Работает в фоновом Service Worker расширения, отвечает за основную бизнес-логику.

**Основные файлы**
- `scripts/background.js`

**Основные процессы**
1. **Перехват и модификация запросов** (`handleRequestBody`)
   - Проверка, является ли диалог новым
   - Построение и инъекция System Prompt
   - Поддержка многопутевой инъекции

2. **Разбор ответов** (`handleResponseChunk`, `handleResponseComplete`)
   - Разбор потокового ответа в реальном времени
   - Обнаружение команд вызова инструментов
   - Дедупликация для предотвращения повторных срабатываний

3. **Выполнение инструментов** (`handleExecuteTool`, `handleListTools`)
   - Вызов API мостового сервиса
   - Форматирование результатов инструментов
   - Умная инъекция в поле ввода

4. **Обработка ошибок** (`handleToolError`)
   - Извлечение подробной информации об ошибке
   - Обратная связь с ИИ-моделью
   - Отображение на панели состояния

### 2. Модульные компоненты

#### 2.1 API-клиент (`modules/api_client.js`)

Инкапсулирует всё взаимодействие с мостовым сервисом.

**Основные методы**
```javascript
export async function getServices()       // Получить список сервисов
export async function getToolsByServer()  // Получить список инструментов сервиса
export async function executeTool()       // Выполнить инструмент
export async function getConfig()         // Получить конфигурацию
export async function updateConfig()      // Обновить конфигурацию
```

**Особенности**
- Автоматический контроль тайм-аута
- Единая обработка ошибок
- Динамическая настройка порта

#### 2.2 Построитель подсказок (`modules/prompt_builder.js`)

Отвечает за построение всех промптов, связанных с MCP.

**Основные методы**
```javascript
export function buildInitialPrompt(services)        // Построить начальный промпт
export function buildReminderPrompt()               // Построить напоминающий промпт
export function formatToolResultForModel()          // Форматировать результат инструмента
export function formatToolErrorForModel()           // Форматировать информацию об ошибке
```

**Принципы дизайна**
- Чистые функции без побочных эффектов
- Чёткий структурированный текст
- Формат, легко понимаемый моделью

#### 2.3 Инъектор ввода (`modules/input_injector.js`)

Умная вставка текста в различные типы полей ввода с последующей отправкой.

**Поддерживаемые типы ввода**
- Элементы `<textarea>`
- Элементы `contenteditable`
- Пользовательские компоненты ввода

**Умная отправка**
- Поддержка нескольких способов отправки (Enter, Ctrl+Enter, нажатие кнопки)
- Автоматическое ожидание обновления UI
- Предотвращение многократной отправки

### 3. Компоненты UI

#### 3.1 Панель состояния (`ui/status_panel.js`)

Постоянно отображаемое плавающее окно в правом нижнем углу страницы, показывающее состояние вызова инструментов.

**Основные функции**
- Обновление состояния в реальном времени
- Сворачивание/разворачивание
- Поддержка ручного ввода как резервного варианта
- Функция повторного обнаружения

**Типы состояний**
- `EXECUTING` — выполняется
- `SUCCESS` — успех
- `ERROR` — ошибка
- `IDLE` — ожидание

#### 3.2 Диалог подтверждения (`ui/confirm_dialog.js`)

Используется для отображения подсказок при загрузке страницы и подтверждения важных действий.

**Особенности**
- Поддержка настраиваемого заголовка, сообщения, текста кнопок
- Поддержка опции «Больше не показывать»
- Поддержка нескольких типов (default, warning, info)

### 4. Система конфигурации

#### 4.1 Конфигурация сайтов (`config/api_list.json`)

Определяет поддерживаемые ИИ-платформы и их конфигурацию.

**Основные поля**
- `name`: идентификатор платформы
- `hostname`: доменное имя
- `api`: список путей API
- `promptPath`: путь для инъекции промпта
- `response`: конфигурация разбора ответа
- `uiParsing`: конфигурация UI-разбора
- `input`: конфигурация поля ввода
- `newConversationFlag`: правило определения нового диалога

#### 4.2 Конфигурация сервисов MCP

Хранится в системном каталоге в файле `mcp-config.json`.

**Расположение конфигурации**
- Windows: `%APPDATA%\mcp-bridge\config\mcp-config.json`
- macOS: `~/Library/Application Support/mcp-bridge/config/mcp-config.json`
- Linux: `~/.config/mcp-bridge/config/mcp-config.json`

**Формат**
```json
{
  "mcpServers": {
    "service_name": {
      "enabled": true,
      "command": "executable",
      "args": ["arg1", "arg2"],
      "description": "Описание сервиса"
    }
  }
}
```

## Потоки данных

### 1. Процесс начала нового диалога

```
Пользователь начинает новый диалог на ИИ-платформе
        ↓
Скрипт страницы перехватывает Fetch/XHR запрос
        ↓
Фоновый скрипт определяет, что это новый диалог
        ↓
Вызов мостового сервиса для получения списка инструментов
        ↓
Построение System Prompt и инъекция в тело запроса
        ↓
Запрос продолжает отправку на ИИ-платформу
        ↓
Панель состояния показывает "System Prompt внедрён"
```

### 2. Процесс вызова инструмента

```
ИИ выводит ответ, содержащий тег <tool_code>
        ↓
Фоновый скрипт разбирает потоковый ответ в реальном времени
        ↓
Обнаружена полная команда вызова инструмента
        ↓
Проверка на дубликаты (предотвращение повторного срабатывания)
        ↓
Определение типа инструмента
        ├─ list_tools_in_service
        │       ↓
        │  Вызов мостового сервиса для получения списка инструментов
        │       ↓
        │  Форматирование в массив JSON
        │
        └─ Другие инструменты
                ↓
           Вызов мостового сервиса для выполнения инструмента
                ↓
           Получение результата выполнения
        ↓
Форматирование результата в Markdown
        ↓
Умная инъекция в поле ввода и автоматическая отправка
        ↓
Панель состояния показывает состояние выполнения
```

### 3. Процесс четырёхуровневой защиты

```
Попытка разбора вызова инструмента через API
        ↓
     Успех? ─── Да ──→ Выполнить инструмент
        ↓ Нет
Попытка разбора через UI DOM
        ↓
     Успех? ─── Да ──→ Выполнить инструмент
        ↓ Нет
Пользователь нажимает кнопку "Повторное обнаружение"
        ↓
Повторный разбор из последнего сообщения
        ↓
     Успех? ─── Да ──→ Выполнить инструмент
        ↓ Нет
Пользователь копирует и вставляет в поле ручного ввода
        ↓
Разбор и выполнение инструмента
```

## Ключевые технические решения

### 1. Почему используется трёхуровневая архитектура?

**Проблема**: как позволить ИИ в браузере вызывать локальные инструменты?

**Сравнение решений**

| Решение | Преимущества | Недостатки |
|---------|--------------|------------|
| Браузерное расширение напрямую вызывает инструменты | Просто | Ограничения безопасности браузера, невозможно выполнять локальные программы |
| Браузерное расширение + Native Messaging | Возможность вызова локальных программ | Сложная настройка, трудности с кроссплатформенностью |
| **Браузерное расширение + HTTP-сервис + MCP** | Гибкое разделение, лёгкость расширения | Требуется запуск дополнительного сервиса |

**Причина выбора**: HTTP-сервис в качестве промежуточного слоя решает ограничения безопасности браузера и через протокол MCP обеспечивает стандартизацию экосистемы инструментов.

### 2. Почему используется Manifest V3?

**Контекст**: Chrome постепенно отказывается от Manifest V2.

**Преимущества**
- Service Worker легче, чем Background Page
- Повышенная безопасность и защита конфиденциальности
- Долгосрочная поддержка в будущем

**Проблемы и решения**
- ❌ Невозможно напрямую внедрять скрипты в MAIN world
- ✅ Решается через конфигурацию `world: "MAIN"`

### 3. Почему нужен четырёхуровневый механизм защиты?

**Проблема**: успешность разбора SSE-потоковых ответов на разных платформах различается.

**Статистика** (на основе тестов)
- DeepSeek: успешность API-разбора ~60%, UI-разбора ~95%
- Tongyi Qianwen: успешность API-разбора ~80%, UI-разбора ~99%
- Doubao: успешность API-разбора ~70%, UI-разбора ~90%

**Решение**: многоуровневая защита, обеспечивающая итоговую успешность, близкую к 100%.

### 4. Почему используется умная инъекция ввода, а не обновление страницы?

**Старое решение**: сохранение результата инструмента, затем обновление страницы для запуска инъекции.

**Проблемы**
- Плохой пользовательский опыт (мерцание страницы)
- Возможная потеря истории диалога
- Не подходит для одностраничных приложений

**Новое решение**: прямая инъекция результата в поле ввода и имитация отправки.

**Преимущества**
- Бесшовный опыт
- Сохранение истории диалога
- Поддержка всех платформ

### 5. Почему поддерживается многопутевая инъекция?

**Контекст**: структура тела запроса различается на разных ИИ-платформах.

**Пример**
```javascript
// Tencent Yuanbao использует два поля одновременно
"promptPath": ["prompt", "displayPrompt"]

// Фоновый скрипт внедряет промпт по обоим путям
for (const path of promptPaths) {
  setByPath(bodyJson, path, finalPrompt, siteConfig);
}
```

**Преимущества**: не нужно изучать внутреннюю логику платформы, конфигурация покрывает все возможные пути.

## Дизайн расширяемости

### 1. Добавление поддержки новой платформы

Достаточно добавить конфигурацию в `config/api_list.json`, не изменяя код.

**Шаги**
1. Проанализировать сетевые запросы целевой платформы
2. Определить путь API и путь для инъекции промпта
3. Настроить правила разбора ответа
4. Настроить селектор поля ввода

**Пример**: добавление поддержки Claude Web
```json
{
  "name": "claude",
  "hostname": "claude.ai",
  "label": "Claude",
  "api": ["/api/chat"],
  "promptPath": "prompt",
  "response": {
    "type": "sse",
    "contentPaths": ["completion"]
  },
  "input": {
    "selector": "div[contenteditable='true']",
    "submitKey": "Enter"
  }
}
```

### 2. Добавление нового инструмента MCP

Достаточно изменить `mcp-config.json`, мостовой сервис загрузит его автоматически.

**Шаги**
1. Получить исполняемый файл или имя пакета инструмента MCP
2. Добавить в файл конфигурации
3. Перезапустить мостовой сервис или вызвать API `/reload`

**Пример**: добавление инструмента Postgres
```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@localhost/db"],
      "description": "Доступ к базе данных PostgreSQL"
    }
  }
}
```

### 3. Настройка шаблонов промптов

Через изменение функций-шаблонов в `modules/prompt_builder.js`.

**Точки расширения**
- `buildInitialPrompt()` — начальный промпт
- `buildReminderPrompt()` — напоминающий промпт
- `formatToolResultForModel()` — форматирование результата инструмента
- `formatToolErrorForModel()` — форматирование информации об ошибке

### 4. Добавление новых компонентов UI

Все компоненты UI модульны и могут разрабатываться и тестироваться независимо.

**Пример**: добавление панели истории инструментов
```javascript
// ui/tool_history.js
export class ToolHistory {
  constructor() {
    this.history = [];
  }
  
  add(toolName, args, result) {
    this.history.push({ toolName, args, result, timestamp: Date.now() });
  }
  
  render() {
    // Отрисовка UI истории
  }
}
```

### 5. Расширение API мостового сервиса

Мостовой сервис использует Flask, добавление нового API очень просто.

**Пример**: добавление API поиска инструментов

## Оптимизация производительности

### 1. Оптимизация перехвата запросов

- **Проблема**: перехват всех запросов влияет на производительность
- **Оптимизация**: перехватывать только запросы, попадающие в список API

```javascript
// Быстрое сопоставление пути
if (!apis.some(api => url.includes(api))) {
  return; // не перехватывать
}
```

### 2. Оптимизация разбора ответов

- **Проблема**: каждый SSE-чанк вызывает разбор
- **Оптимизация**: механизм дедупликации, предотвращающий повторную обработку

```javascript
// Проверка, был ли уже обработан этот вызов инструмента
if (state.currentToolCall === toolCallMatch[0]) {
  return; // пропустить
}
```

### 3. Оптимизация кэширования конфигурации

- **Проблема**: частые чтения chrome.storage влияют на производительность
- **Оптимизация**: кэширование конфигурации в background.js

```javascript
let cachedApiList = null;

async function getApiList() {
  if (!cachedApiList) {
    const { api_list } = await chrome.storage.local.get('api_list');
    cachedApiList = api_list;
  }
  return cachedApiList;
}
```
